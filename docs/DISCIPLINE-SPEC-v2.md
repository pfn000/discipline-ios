# Discipline v2 — product and engineering specification
24 October 2026 · NCOM / Saidie · status: specification and staged implementation; **not a claim that the cap is bypassed in today's IPA**

## The promise and its real boundary
Saidie said “that's why discipline will/should natively built in as well as trollstore” (ab5d37d1), then “Exactly” to Discipline itself becoming the installer with a LiveContainer-style guest runtime and a conditional TrollStore mode (conversation m:e3d5c38c). The desired result: one Discipline home-screen app hosts imported guest IPAs so the guests use no additional free-account app slots. Apple's free development account allows at most three installed apps per device, ten App IDs per seven-day interval, and a seven-day provisioning expiry [1]. **A container does not remove the seven-day expiry of its own host**; the host still must be signed, verified and refreshed. The guest apps' compatibility and permissions are not guaranteed. Her iPhone 17 Pro was reported on iOS 26.2 beta 4; her attempted v0.1.0 install first hit the three-app cap and later “integrity could not be verified.” Those are separate failures; neither proves Discipline opened. The trust/Developer Mode steps were already sent.

## Native container architecture: what it would take
LiveContainer itself is AGPL-3.0, not permissive code [2]. It describes an app launcher (not an emulator): changes guest Mach-O `__PAGEZERO`, converts `MH_EXECUTE` to `MH_DYLIB`, injects TweakLoader, hooks dyld's executable path and `NSBundle.mainBundle`, `dlopen`s the guest and jumps to its entry point [3]. Under JIT-less operation the guest is signed with the SAME certificate as the LiveContainer host; below iOS 26 JIT can instead bypass signing when available [2,3]. Certificate import from SideStore/AltStore and an entitlement diagnostic are required in its standalone setup [6]. The host's entitlements do **not** become the guest's; app extensions and remote push are not supported, permissions are global, and guest containers are **not sandboxed from each other** [3]. LiveContainer allocates one of 128 keychain access groups per guest container, but those groups must actually be present on the host's signed profile [3,6]. Neither import nor patching alone makes a runnable guest. iOS 26 device loading, codesigning, app groups, dyld patching, JIT-less fallback, keychain migration and launch-after-refresh are release gates, not boxes checked by a simulator build.

**License/product decision:** Vendoring or adapting LiveContainer's implementation into Discipline obligates an AGPL-3.0-compatible release of the combined program's corresponding source and notices [2]; this conflicts with Saidie's description of Ouija Board as proprietary if its code is combined. Do not silently copy/paste LiveContainer, SideStore or SideInstaller code. Options to review with Saidie: make the combined app AGPL-compliant and keep proprietary Ouija on a legally separate component, obtain alternative permission from upstream, or fund an independently developed runtime with a legal review. Until then use API/document handoffs where honest; those are *not* “Discipline itself is the installer.” No private signing keys or exported `.p12` are committed, logged or put in the IPA. A user-provided signing cert would live in Keychain and stay on device; password never enters the repo. Re-signing patched binaries invalidates their prior signature and must be reverified.

**Threat model and acceptance:** Reject path traversal, symlinks escaping extraction root, ZIP bombs, encrypted FairPlay binaries and malicious manifest paths; inspect every nested Mach-O and entitlement. Keep imported IPAs as immutable source and make derived copies. Guest apps sharing a host can read each other's data unless isolation is *actually* enforced; tell users this before running untrusted IPAs. Test on the reported device/OS with 3+ distinct decrypted IPAs (including one SwiftUI app), cold launch, switch, data separation, keychain, document picker, notifications, app groups, reboot, host expiry/refresh. Report each unsupported feature by app instead of claiming arbitrary-app compatibility. Preserve a rollback path to standalone LiveContainer until native mode passes.

## TrollStore gate
TrollStore's own documentation says supported iOS is 14.0 beta 2–16.6.1, 16.7 RC (build 20H18), and 17.0; regular 16.7.x and 17.0.1+ will never work under the known bug [4]. Apple documents the CoreTrust signature-validation fix in 16.7 and 17.0.1 (CVE-2023-41991) [5]. Implement OS version + exact build check, default to “unsupported” for unknown versions; hardware and presence are separate checks, and eligible OS ≠ installed TrollStore. TrollStore uses the `apple-magnifier://install?url=…` scheme, but the normal Magnifier app uses that same scheme when TrollStore is absent, so `canOpenURL` alone is NOT proof TrollStore exists [4]. A local IPA should be exported to Files/share sheet for explicit selection; don't upload it just to manufacture an install URL. For iOS 26.2 show: “TrollStore is unavailable on this iOS version. This app cannot turn it on.” Never install or ask users to downgrade based on version text.

## Remaining wishlist, with hard lines
- **GitHub auto-update** (dbf9e048): manual release discovery/IPA download is already present; don't mislabel an in-app refresh as background auto-update. Build opt-in repo subscriptions, check via BackgroundTasks best-effort and on app foreground; verify assets and show version notes before import. Install/sign still depends on guest runtime/available companion. GitHub source may have non-IPA releases; don't infer one by extension alone.
- **Automatic certificate refresh** (a3597170, b49658d2, afc91044): request is toggle, native automatic tracking, expiry recorded without user entry, silently re-sign before expiry. Not in v0.1. Real implementation needs an Apple-signing backend (and valid certificate/private key obtained securely), extension/app group approvals, refresh scheduling with success acknowledgement. iOS background tasks are not time guarantees. App must show “last confirmed signed at,” “expires,” “next attempted,” and exact errors. Never set expiry from a guessed signing date or falsely mark refreshed.
- **All-app inventory** (d9e4c8b1): no public API to list every installed app/process. Show guest/library/tracked records with origin and explicitly label the incomplete scope. No fake “all apps” toggle on iOS 26.
- **Unofficial stores / EU-only apps** (dbf9e048): parse compatible source lists, let user select a source and inspect signer/origin; Apple's alternative distribution rules still apply in eligible regions. Apps encrypted with FairPlay or built for an incompatible OS/architecture won't run as guest apps by virtue of a catalog link.
- **One-tap IPA import/download** (dbf9e048): document picker/share and authenticated transport are possible; an IPA discovered by Safari cannot be read from another app's private Downloads until explicitly handed over. “Authenticate” must name which credential and stay on-device; neither authorizes bypassing Apple's code signing.
- **NCOM Ouija activation** (dbf9e048, 94e98810): tap visible title 25 times OR scan a signed NCOM QR grant. No secret QR aesthetic is itself cryptographic authentication. A real grant needs issuer public key pinned in app, short-lived nonce, offline signature verification, revocation policy, and never a hard-coded private key; not shipped in v2 increment. Developer warning precedes explicit consent to each optional prototype feature.
